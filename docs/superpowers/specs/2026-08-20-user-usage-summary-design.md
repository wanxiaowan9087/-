# 全用户使用总结与数据生命周期设计

## 1. 目标与范围

为每个已登录用户提供基于真实站内数据的“使用总结”。总结在每轮助手消息成功完成后异步更新，用户在对话中请求总结时读取最新快照。该功能不阻塞流式回答，不伪造设备业务数据，也不向普通用户开放知识库上传入口。

本设计仅覆盖平台对话、长期记忆、产品推荐和站内产品浏览行为的汇总；外部设备清扫数据继续沿用已有授权映射和报告链路。

## 2. 核心约束

- 所有原始数据、结构化数据、缓存键、任务、快照和查询必须以认证用户的 `user_id` 隔离。客户端不得传入任意目标用户 ID。
- 任何推荐记录只保存产品目录稳定标识（`product_id` 与 `model_code`）；前端通过现有产品目录映射图片、价格、详情和 3D 页面，禁止复制产品详情到用户记录中。
- 仅用户明确表达的事实和偏好可以写入长期记忆，且必须记录 `source_message_id`、置信度、提取版本和状态。
- 设备使用数据只能来自真实、已授权的外部业务数据源。没有授权映射或业务记录时，返回“暂无设备使用数据”，不得由模型推测或由演示 CSV 补全。
- 汇总或记忆提取失败不得中断当前聊天；失败必须可追踪、可重试，且不产生虚假的成功快照。

## 3. 数据模型

继续使用既有 `users`、`sessions`、`messages`、`runs`、`memories` 和产品目录。新增如下表。

### 3.1 `user_usage_events`

存储可审计的站内行为明细：`user_id`、`session_id`、可选 `message_id`、`event_type`、JSON 元数据、`product_id`、`model_code`、`occurred_at`。

事件类型至少包括：`product_recommended`、`product_detail_viewed`、`product_3d_viewed`、`usage_summary_requested`。索引为 `(user_id, occurred_at DESC, id)`，推荐查询额外索引 `(user_id, model_code, occurred_at DESC)`。

### 3.2 `summary_update_jobs`

存储每轮完成后的汇总任务：`id`、`user_id`、`session_id`、触发助手消息 ID、状态、尝试次数、最大尝试次数、可重试时间、错误代码、错误摘要、创建/处理/完成时间。

唯一约束覆盖触发助手消息 ID，确保同一轮回答重复投递不会生成多条任务。待处理任务按 `(status, next_attempt_at, created_at)` 领取；领取时使用数据库行锁避免并发 worker 重复处理。

### 3.3 `user_summary_snapshots`

存储可读取的总结快照：`id`、`user_id`、`version`、`status`、`summary_json`、`display_summary`、数据时间范围、生成时间、来源消息截止位置、生成器版本和可选错误信息。

每个用户只有一个 `status=active` 的快照；新快照先完整写入，再在同一事务内切换 active 状态。索引为 `(user_id, generated_at DESC, id)`。

### 3.4 结构化快照内容

`summary_json` 固定包含以下字段，缺少数据时使用 `null`、空数组或明确状态而非编造文本：

```json
{
  "conversation_overview": {
    "session_count": 0,
    "message_count": 0,
    "active_days": 0,
    "top_topics": []
  },
  "facts": [],
  "preferences": [],
  "product_activity": {
    "recommended_models": [],
    "detail_view_count": 0,
    "three_d_view_count": 0
  },
  "device_usage": {
    "status": "unavailable",
    "reason": "no_authorized_external_data"
  },
  "data_through_at": "2026-08-20T00:00:00Z"
}
```

## 4. 更新与读取流程

1. 聊天完成并将助手消息置为 `completed` 后，在同一业务事务内创建 `summary_update_job`；现有 SSE `done` 事件与普通回答不等待任务完成。
2. 后台 worker 领取该任务，以该任务 `user_id` 读取消息、会话、有效长期记忆和行为事件。
3. `MemoryExtractionService` 从本轮用户消息提取明确事实与偏好，沿用现有 memory 状态、来源和置信度模型。用户纠正已有信息时，旧记录置为 `inactive`，保留历史，不直接覆盖。
4. `UserUsageAggregator` 汇总主题、会话数、消息数、推荐与浏览事件。所有产品标识在读取时映射到产品目录，失效目录项明确标记为不可用。
5. `UserSummaryService` 生成新的结构化快照和中文展示摘要，成功后标记任务完成；可恢复失败按有限次数退避重试，达到上限后标记失败并记录脱敏错误信息。
6. Agent 识别到“总结我的使用情况”等意图后，通过 MCP 工具 `get_user_usage_summary` 读取当前认证用户的 active 快照。没有快照或数据为空时返回明确的空状态说明。
7. 提供只读的 `GET /me/usage-summary` 给前端未来的“我的总结”页面。该接口只返回当前令牌所属用户的最新快照，不接受 `user_id` 参数。

外部设备报告保留已有强制工具顺序和授权映射；其结果只能作为 `device_usage` 的真实来源补充，不能替代平台使用总结。

## 5. 生命周期与定期清理

每日低峰期运行一个可重复、带批处理上限的清理 worker。每次运行记录开始/结束、每类扫描和删除数量、失败原因；日志不记录消息正文、令牌或个人敏感字段。

| 数据 | 周期 | 操作 |
| --- | --- | --- |
| 流式过程、运行追踪、错误日志 | 14 天 | 分批硬删除 |
| 行为明细 | 60 天 | 确认已有最新总结快照后分批删除 |
| 完整会话消息 | 90 天 | 先校验对应用户的有效总结快照涵盖该时间范围，再删除消息原文 |
| 总结快照 | 最近 12 个 | 删除超出数量的非 active 旧快照 |
| 已失效长期记忆 | 30 天 | 分批硬删除 |
| 用户主动删除的会话或账号 | 7 天回收期 | 删除关联数据，并保持外键完整性 |

清理任务在下列条件之一不满足时跳过受影响批次并告警：有效快照缺失、快照覆盖时间不足、数据库事务失败、任务锁无法取得。不会为腾出空间而删除用户当前有效的长期记忆或 active 总结快照。

## 6. API、MCP 与权限

- 新增只读 `GET /me/usage-summary`，响应沿用标准 Envelope、`request_id` 与统一错误模型。
- 新增 MCP 工具 `get_user_usage_summary`，运行上下文从认证身份取得 `user_id`，工具参数不允许覆盖该身份。
- 行为事件由现有详情页、3D 页面和推荐卡片操作通过受认证 API 写入，不提供可伪造任意用户事件的通用接口。
- OpenAPI、Pydantic Schema、FastAPI 路由和前端 DTO 必须在契约变更审批后同步更新；不得增加语义重复的总结接口。

## 7. 失败、审计与安全

- 任务失败只影响总结时效，不影响会话、流式回答和历史消息写入。
- 任务重试必须有明确最大次数和退避时间；重复投递、服务重启和多 worker 并发不重复生成同一轮对应的任务。
- 所有仓储方法以 `user_id` 为必要参数并在 SQL 条件中过滤，禁止先按资源 ID 查询再在应用层判断归属。
- 结构化记忆、快照、事件和清理日志均记录可追溯来源；模型不得根据无依据的文本创建事实。
- 删除遵循上述生命周期，并允许通过数据库备份完成灾难恢复；应用层不向用户暴露其他用户的快照、任务或行为记录。

## 8. 验收标准

1. 两名用户创建会话、产生记忆和推荐记录后，无法通过 API、MCP、缓存或资源 ID 读取对方的记录。
2. 每轮助手消息 `completed` 后只创建一个汇总任务，当前 SSE 正常结束且不等待任务处理。
3. worker 成功处理任务后，最新快照包含真实会话统计、可追溯事实/偏好和推荐型号标识。
4. 服务重启后，未完成或可重试任务可恢复；不可恢复失败保留脱敏的错误状态。
5. 无外部授权或记录的用户得到“暂无设备使用数据”，不会读取管理员演示数据。
6. 推荐型号能通过产品目录在前端展示正确图片、价格，并跳转详情与 3D 页面。
7. 清理任务只删除超过周期的可清理数据；没有覆盖范围足够的 active 快照时，不删除对应的 90 天前消息。
8. pytest 覆盖仓储隔离、并发领取、重试、快照原子切换和清理边界；Apifox/ASGI 场景覆盖认证、读取总结、空数据、越权和聊天后更新；最终候选 SHA 通过既有质量门。

## 9. 非目标

- 不把管理员的外部设备演示数据扩展为普通用户假数据。
- 不在本次实现中增加向量检索、知识库上传、计费、消息导出或新的外部分析服务。
- 不改变已存在的产品目录、产品详情和 3D 展示的业务语义。
