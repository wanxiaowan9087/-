# 文档解析与知识库管理

## 切片配置

统一由 `backend/app/rag/chunking.py` 的 `DocumentChunker` 控制：默认每片约 600 个字符，相邻切片重叠 80 个字符，按字符而不是 Token 计算，最小切片长度为 80。断点优先选择空行、换行、中文句末标点、英文句号和空格，避免在完整句子中间截断。

## 支持格式与策略

| 格式 | 解析方式 | 切片上下文 |
| --- | --- | --- |
| `.txt` | UTF-8 解码 | 递归文本切分 |
| `.md` / `.markdown` | UTF-8 解码，按标题分段 | 保留标题元数据 |
| `.pdf` | `pypdf` 按页提取文本 | 保留页码；扫描件需先 OCR |
| `.xlsx` | `openpyxl` 读取工作表，首行作为字段名 | 保留工作表、行号和字段值 |

PDF 和 Excel 解析后都会转换成统一的 `DocumentRecord`，之后复用同一个切片、Embedding、pgvector 和 BM25 流程。Excel 的每一行会形成类似 `字段=值；字段=值` 的检索文本，避免只把单元格孤立地向量化。

`.xls` 暂不接收，避免引入旧格式解析器；可先另存为 `.xlsx`，后续再按部署环境增加 `xlrd` 转换支持。图片型 PDF 当前会明确提示需要 OCR，不会把空文本错误写入知识库。

## 已入库文档 CRUD

管理员接口：

- `GET /knowledge/files`：列表查询
- `GET /knowledge/files/{document_id}`：详情查询
- `PATCH /knowledge/files/{document_id}`：修改标题或展示文件名；修改标题后自动重新索引
- `DELETE /knowledge/files/{document_id}`：删除源文件、Manifest、pgvector chunks 和 BM25 索引

上传仍使用 SHA-256 去重、同名冲突和内容相似度预警。物理文件名保留内容摘要后缀，修改展示文件名不会破坏文档 ID 或引用关系。
