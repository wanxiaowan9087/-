## 3. 阿里云号码认证接入

后端新增号码认证适配器，调用：

- `dypnsapi:SendSmsVerifyCode`：针对 `register`、`password_reset`、`admin_phone_binding` 用途发送验证码。
- `dypnsapi:CheckSmsVerifyCode`：在注册、重置密码或管理员绑定事务前校验验证码。

阿里云平台签名与已审核登录/注册模板 `100001` 固定在服务端配置。前端不得传入签名、模板、AccessKey、Secret、验证码策略或任意阿里云请求参数。

认证适配器从以下标准环境变量读取最小权限 RAM 凭证：

```text
ALIBABA_CLOUD_ACCESS_KEY_ID
ALIBABA_CLOUD_ACCESS_KEY_SECRET
APP_ALIYUN_SMS_SIGN_NAME
APP_ALIYUN_SMS_TEMPLATE_CODE
```

生产环境可用 ECS RAM Role 时应优先使用角色，不在应用配置中长期保存静态 AccessKey。服务日志只记录凭证是否可用，不输出任何凭证值、签名请求、验证码或完整供应商响应。

发送接口不因供应商超时而盲目重试。阿里云请求标识写入审计记录，后续通过供应商回执或受控重试策略处理。验证码核验成功后按阿里云语义一次性消费。

## 5. 数据设计与迁移

### 5.1 `users`

保留既有不可变 `id` 与角色，新增：

- `phone_ciphertext`：使用专用服务端密钥加密后的 E.164 中国大陆手机号；不向普通 API 返回。
- `phone_lookup_digest`：使用独立 HMAC 密钥生成的不可逆检索摘要，唯一约束用于查重和登录定位。
- `phone_key_version`：用于未来密钥轮换。
- `phone_verified_at`：验证码验证完成时间。
- `tokens_revoked_after`：密码重置或高风险安全操作后废止旧令牌的时间水位。

旧 `username` 只保留为迁移兼容数据，不出现在新的注册、登录、个人资料或前端接口中；数据库迁移完成后为 `xiaow` 写入加密手机号、检索摘要和验证时间。

### 5.2 新表

`agreement_versions`：协议类型、版本、正文、内容摘要、生效时间、状态、创建时间。

`user_agreement_consents`：用户 ID、协议版本 ID、协议摘要、同意时间、请求 ID、IP/UA 摘要；同一用户可保留不同版本的历史同意记录。

`sms_verification_audits`：用户 ID（可空）、用途、脱敏手机号、号码摘要、阿里云请求标识、状态、供应商错误码、请求 ID、IP/UA 摘要与时间。严禁保存验证码、手机号明文和短信正文。

`security_audit_logs`：认证、令牌、权限、管理员、限流、关键数据删除与异常访问的追加式安全日志，含 actor `user_id`（可空）、事件类型、结果、请求 ID、IP/UA 摘要、最小化元数据和时间。

数据库加密密钥、检索摘要密钥不得存入表、迁移文件、代码、测试快照或 Git 仓库。数据库访问层需要每个用户资源查询显式使用认证 `user_id`。

## 6. HTTP 契约

OpenAPI 变更经用户批准后，新增或变更如下接口：

| 方法与路径 | 用途 | 认证 |
| --- | --- | --- |
| `POST /auth/sms-codes` | 发送用途受限的阿里云验证码 | 匿名，严格限流 |
| `POST /auth/register` | 验证手机号、协议同意后原子创建账号 | 匿名 |
| `POST /auth/login` | 手机号与密码登录 | 匿名，严格限流 |
| `POST /auth/password-resets` | 短信校验后重置密码并撤销旧令牌 | 匿名，严格限流 |
| `GET /legal/user-agreement` | 获取当前用户协议版本与正文 | 匿名 |
| `GET /legal/privacy-policy` | 获取当前隐私政策版本与正文 | 匿名 |

`POST /auth/sms-codes` 只允许 `register` 和 `password_reset`；管理员初始化绑定为受控的迁移/运维操作，不向普通客户端公开伪造管理员绑定用途。返回体不暴露完整手机号、验证码或供应商敏感字段。

所有接口沿用标准 Envelope、`request_id`、Pydantic 验证、标准错误模型与 API 限流语义。前端 DTO 由 OpenAPI 更新同步，不复制出私有同义类型。

## 7. 频率限制、错误与降级

Redis 保存短生命周期的限流计数，不保存验证码。最小限制：同手机号 60 秒内最多发送 1 次、1 小时最多 5 次、24 小时最多 10 次；同 IP 与同匿名会话还需较严格的独立上限。供应商限制更严格时以供应商限制为准。

手机号格式、协议未同意、验证码无效/过期、手机号已注册、密码不合规均返回统一且不泄露账号枚举信息的验证错误。登录、找回密码与验证码发送对于不存在手机号使用相同的外部响应语义。

阿里云、Redis 或数据库不可用时：不发送或不确认验证码，不创建账号，不重置密码；返回可重试的受控错误并写入脱敏安全日志。禁止本地伪造验证码、降级为跳过验证或因供应商错误而直接完成注册。

## 8. 数据留存与清理

完整对话消息等业务数据遵循已批准的生命周期策略。安全日志与短信认证审计不适用 14 天调试日志周期：依据《中华人民共和国网络安全法》第二十一条，网络安全日志至少保存六个月。

| 数据 | 最低保留期 |
| --- | ---: |
| 安全日志：登录、认证、验证码、令牌、权限、管理员、限流、关键删除与异常访问 | 180 天 |
| 短信认证审计 | 180 天 |
| 普通运行调试日志 | 14 天 |
| 完整对话消息 | 90 天 |
| 行为明细 | 60 天 |

安全日志不记录密码、验证码、AccessKey、Secret、对话全文或手机号明文。每日清理任务只能删除超过期限的记录，分批处理并记录清理数量、失败原因和执行人/任务标识；不得删除仍在法定或安全审计期内的数据。
