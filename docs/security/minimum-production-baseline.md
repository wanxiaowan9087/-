# 最小生产安全与运维基线

本项目定位为可演示、可部署的单租户实习作品，不构建复杂 IAM，但以下要求必须可测试。

## 1. 身份与权限

- 演示环境使用受信任身份头或可替换的认证 Adapter；生产模式禁止匿名访问业务接口。
- 角色只有 `user` 与 `reviewer`：用户只能访问自己的会话、记忆、反馈和 Run；reviewer 额外访问审核队列并作出决定。
- `/health/live` 可匿名；`/health/ready` 不返回依赖详情或密钥。
- 对象级权限必须在服务端校验，禁止仅靠前端隐藏按钮。

## 2. 浏览器边界

- CORS 采用环境变量白名单；生产模式禁止 `*` 与凭据同时启用。
- 若使用 Cookie 身份，所有写操作必须启用 SameSite、Secure 与 CSRF 防护；若使用 Bearer Token，则禁止落入 URL 和日志。
- CSP、`X-Content-Type-Options`、`Referrer-Policy` 由反向代理或应用统一配置。

## 3. 数据与隐私

- 默认保留：消息、Run、引用、反馈和审核记录 90 天；长期记忆保留至用户删除或停用。
- 删除会话或记忆采用授权校验和审计；备份中的数据按备份周期自然过期，不承诺即时物理抹除。
- 日志不得包含完整 Prompt、原始用户消息、Token、密钥或可直接识别个人的信息；必要字段先脱敏。
- Prompt 注入文本视为不可信数据，不提升为系统指令。

## 4. 可用性与恢复

- `/health/live` 只检查进程存活；`/health/ready` 检查数据库，并以降级字段报告 Redis、向量库与模型可用性。
- PostgreSQL 每日备份，至少保留 7 个恢复点；发布前在非生产环境完成一次恢复演练并记录结果。
- 数据库迁移必须有前滚和回滚说明；不可逆迁移必须单独获得用户批准。
- 外部模型、工具、Redis、向量库均配置连接/读取超时；重试有上限并带抖动退避。

## 5. 观测

- 日志至少关联 `request_id`、`session_id`、`run_id`，并记录错误类别、耗时和降级状态。
- 最低指标：请求量、5xx 比例、P95 延迟、流式中断率、模型/工具失败率、审核触发率、检索无依据率。
- 默认告警门：连续 5 分钟 5xx 比例超过 5%，或 readiness 连续 3 次失败。演示环境可只输出告警事件。

## 6. 供应链

- Python 与 Node 依赖必须锁定版本。
- CI 执行依赖漏洞扫描、密钥扫描、静态检查和容器镜像高危漏洞扫描。
- 高危或严重漏洞不得进入最终集成分支；若无可用修复，必须记录影响、缓解措施和用户批准的临时例外。
- 容器使用非 root 用户、最小基础镜像和只读配置；密钥通过环境变量或 secret 注入。
