# ZENMOP 知识库导入清单规范

## 1. 适用范围

本文定义从审核资料到 PostgreSQL + pgvector 的正式导入清单格式。爬虫生成的 `content_path` 清单不是正式导入清单，必须先人工审核并转换。

## 2. JSONL 记录格式

每行一个文档对象，UTF-8 编码，不使用 Markdown 包裹：

```json
{"source":"kb://zenmop/model/s8-luna/charging","title":"S8-LUNA 皓月回充与充电排查","document_type":"text","version":"2026-09-08","content":"...审核后的正文...","metadata":{"brand":"ZENMOP","model":"S8-LUNA","product_id":"s8-luna","topic":"charging","review_status":"approved","reviewer":"user","source_url":"https://..."}}
```

## 3. 必填与选填字段

| 字段 | 要求 |
| --- | --- |
| `source` | 必填、稳定且唯一；推荐使用 `kb://zenmop/...`，原始网址放入 `metadata.source_url` |
| `title` | 必填，包含型号和主题，避免“资料1”等无意义标题 |
| `document_type` | 必填，当前使用 `text`；必须与代码中的 `DocumentType` 枚举一致 |
| `content` | 必填，正文必须已审核；不能只填文件路径、搜索摘要或导航文本 |
| `version` | 必填，使用资料发布日期或审核日期；内容变化必须升版本 |
| `metadata` | 推荐包含品牌、型号、产品 ID、主题、来源、审核状态和适用场景 |
| `document_id` | 可选；省略时由程序按 source 稳定生成，不要每次随机生成 |
| `pages` | 可选，适用于 PDF 页码或章节定位 |

## 4. 审核门槛

- 标题、正文和元数据中的型号必须一致；通用建议不能写成某型号已具备的功能。
- 电池容量、充电时长、吸力、越障等未核验参数只能写“以正式规格书为准”。
- 每个结论必须能追溯到原始来源；无法追溯的营销描述不得进入生产清单。
- 删除导航、价格列表、重复段落和与扫地机器人无关的页面内容。
- 安全红线、停止使用条件和售后升级条件必须保留，不能为了压缩长度删除。

## 5. 导入前检查

```bash
python -m backend.scripts.ingest_knowledge --manifest <正式清单路径> --dry-run
```

`dry-run` 通过只代表字段和 JSONL 格式正确，不代表内容已审核。正式导入前还要检查重复 source、版本变化、型号元数据和评测样本覆盖；导入后使用 pgvector 检索和 BM25 融合路径做抽样验证。

## 6. 版本与回滚

同一 `source` 的修订应更新 `version` 和审核记录，保留旧清单及 SHA-256。禁止直接编辑生产库中的单条向量来“修复”内容；应生成新清单、执行导入、评测通过后再按版本策略停用旧记录。
