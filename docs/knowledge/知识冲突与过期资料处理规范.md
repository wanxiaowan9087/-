# ZENMOP 知识冲突与过期资料处理规范

## 1. 冲突类型

| 类型 | 示例 | 默认处理 |
| --- | --- | --- |
| 型号冲突 | 文档把 X9-EDGE 写成支持自动上下水 | 以型号目录和审核过的型号文档为准，错误来源隔离 |
| 版本冲突 | 新旧说明对同一功能步骤不同 | 保留版本字段；新版本生效前完成回归验证 |
| 安全冲突 | 一份资料允许湿手操作，另一份禁止 | 采用更严格的安全规则，标记冲突并复核原始来源 |
| 数值冲突 | 电池容量、吸力或温度不一致 | 不写死数值，转为“以正式规格书为准”直到核验 |
| 场景冲突 | 木地板既推荐高水量又推荐低水量 | 按地板材质和正式说明拆分条件，不输出无条件建议 |

## 2. 处理步骤

1. 为冲突建立记录：`conflict_id`、涉及 source、型号、版本、发现时间和问题描述。
2. 对照原始官方资料、设备铭牌、版本日期和项目型号目录，判断是否是型号、版本或抄录错误。
3. 无法确认时，将结论降级为“不确定/需要查看正式规格书”，并在正文中保留安全边界。
4. 修订文档和正式导入清单，更新版本与校验值；不直接覆盖历史资料。
5. 为冲突相关问题增加评测样本，验证模型不会混用型号或引用旧版本。

## 3. 过期判定

- 来源明确标记停产、服务终止、固件不再支持或配件下架。
- 文档描述的功能、界面、接口或安全要求已被新版本替换。
- 内容来源无法确认，或只剩搜索摘要、价格和营销页面。
- 型号名称与项目目录不一致，无法建立稳定的产品 ID。

过期资料不直接删除：先标记 `deprecated`，从默认检索范围隔离，保留来源、版本和停用原因。只有在确认无审计价值且取得数据删除批准后，才执行物理删除。

## 4. 发布前检查

| 检查项 | 通过条件 |
| --- | --- |
| 型号一致性 | 标题、正文、metadata 和产品目录一致 |
| 版本 | 有发布日期/审核日期，且没有新版本覆盖 |
| 安全 | 没有低于通用安全规范的建议 |
| 引用 | 结论可定位到文档版本和 chunk |
| 评测 | 相关旧问题和新增冲突问题均通过 |

## 5. 冲突记录模板

```text
conflict_id: conflict-YYYYMMDD-序号
model: 型号或“通用”
sources: source@version 列表
description: 冲突内容
decision: 采用/隔离/降级为未知
reason: 原始来源、审核结论和安全依据
affected_eval_cases: case_id 列表
reviewed_by: 审核人
reviewed_at: ISO 8601 时间
```
