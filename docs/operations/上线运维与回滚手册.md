# ZENMOP 上线运维与回滚手册

## 1. 当前部署边界

生产栈为 FastAPI、Vue 前端、PostgreSQL + pgvector、Redis 和 Nginx/HTTPS。向量库是 PostgreSQL 中的 pgvector；Redis 用于缓存/限流等辅助能力，不能作为知识数据的唯一来源。

## 2. 发布前检查

| 检查项 | 要求 |
| --- | --- |
| 代码 | 记录最终 40 位 Git SHA，工作区无未提交的临时数据 |
| 数据 | 正式 JSONL 清单已审核，source、version、metadata 和 SHA 可追溯 |
| 数据库 | Alembic 迁移状态与目标版本一致，pgvector 扩展和索引健康 |
| 评测 | 使用固定语料、固定 Embedding 和评测集运行 RAG 评测，硬阈值通过 |
| 安全 | 环境变量、手机号、Token、Prompt 和日志完成脱敏检查 |
| 备份 | 发布前完成数据库和知识清单备份，并记录恢复位置 |

权威验收命令遵循项目现有质量门：

```bash
python scripts/quality_gate.py all --integration-sha <40位Git提交SHA>
```

## 3. 知识库发布流程

1. 生成新版本正式 JSONL 清单，保留旧版本和校验值。
2. 执行 `python -m backend.scripts.ingest_knowledge --manifest <清单> --dry-run`。
3. 在隔离环境导入并抽样检查 pgvector 检索、BM25 融合、引用版本和型号过滤。
4. 运行 RAG 评测，比较旧/新指标和逐样本差异。
5. 记录发布版本、代码 SHA、迁移版本、清单 SHA、评测报告和操作者。
6. 通过完整质量门后再安排生产发布；不要在生产库直接手工改向量。

## 4. 运行中排查

| 现象 | 检查顺序 | 处理原则 |
| --- | --- | --- |
| 服务未就绪 | FastAPI 健康检查、迁移、数据库连接、Redis | 先恢复依赖，不跳过就绪检查 |
| 检索为空 | pgvector 连接、向量维度、清单版本、索引 | 保留错误和 request_id，不返回无来源猜测 |
| 延迟升高 | PostgreSQL 慢查询、HNSW 索引、Redis 命中、模型耗时 | 先限流和降级，避免直接删除索引或扩大超时 |
| 引用错误 | 文档版本、chunk ID、缓存版本 | 使缓存失效，回到上一份已验证清单 |
| SSE 中断 | FastAPI 日志、反向代理超时、Redis/模型状态 | 返回可识别的 error/done 事件，保留请求追踪 |

## 5. 回滚策略

### 应用回滚

使用上一个已验收的镜像/代码 SHA，执行对应数据库兼容迁移和健康检查。禁止用未验收的本地构建物直接替换线上服务。

### 知识库回滚

恢复上一个已验收的正式清单和版本记录，重新执行 dry-run、导入、抽样检索和 RAG 评测。若新版本引入错误，不通过“删除所有向量”解决；先隔离问题 source，再恢复已知良好版本。

### 数据库回滚

遵循迁移文件提供的升级/降级边界。涉及不可逆迁移时，使用发布前备份恢复到隔离实例，验证后再切换流量；任何破坏性数据操作必须有明确批准和审计记录。

## 6. 事故记录

至少记录：发生时间、影响范围、用户可见症状、代码/清单/迁移 SHA、日志 request_id、处理动作、是否回滚、恢复时间、根因和后续评测样本。事故记录不得包含 Token、手机号明文或用户对话原文。
