# ZENMOP RAG v3 评测报告

## 结论

2026-09-19 在独立临时 PostgreSQL 数据库中完成 v3 真实链路评测。v3 覆盖当前
24 篇逻辑知识资料，共 200 个固定问题，其中 120 个保留自 v2，新增 80 个用于覆盖
新增资料、口语表达、多来源问题、无依据问题和 Prompt 注入。

在双查询规范化、软分类路由和证据门控基础上，新增阿里云
`qwen3.7-text-rerank` Cross-Encoder 重排、Markdown 标题层级与型号元数据、生成后引用选择，
并只在证据语义弱或数值置信度低时限时调用千问改写查询。真实 DashScope
`text-embedding-v4` + pgvector + 云端 Rerank 结果为：Recall@5 87.50% (147/168)，
Recall@10 94.05% (158/168)，MRR@10 0.6795。Prompt 注入防御率达到 100%，无依据
拒答召回率达到 96.88%；但固定标注口径下的引用证据支持率仍只有 42.66%，因此当前版本
不能宣称已经通过全部生产验收。

## 延迟与降级

| 指标 | 结果 |

| 本地降级率 | 0.00% |

交互请求不重试；Rerank 超过 1.2 秒、429、5xx、非法响应或缺少 Key 时立即降级到本地
Lexical Reranker。生产运行复用一个异步 HTTP Client 和 Keep-Alive 连接池，应用关闭时释放。

“引用证据支持率”只表示返回引用命中了人工标注的证据来源，不是 LLM 对最终自然语言
回答进行语义裁判后的忠实度。

以下拆分来自改造前的 v3 基线，仅用于定位问题，不代表上表的优化后逐类结果。这组拆分说明
新增长文本可以处理直接问题，多来源问题也能进入 Top-5；当前最明显的弱项
是口语化短问。后续应优先改查询改写、意图补全和对长文本的 BM25/向量候选分配，而不是
继续扩大 Top-K 掩盖排序问题。

## 与 v2 的关系

v2 历史真实链路使用 13 篇资料、120 个问题，Recall@5 为 85/100，Recall@10 为
97/100。v3 扩大到 24 篇、200 个问题，候选语料和问题分布都发生了变化，因此不能把
`85.00% -> 71.43%` 宣称为同一基准上的性能回退，也不能宣称 v3 “提升”了 v2。

作为压力观察，v3 中保留的 100 个 v2 可回答问题在扩大语料后 Hit@5 为 67/100、
Recall@10 为 82/100，说明新增的大量通用资料与旧型号说明发生了明显候选竞争，需要后续
增加文档类型/型号过滤或分层召回。

## 验证结果与下一步

1. `600/80` 真实链路完整运行成功，逐题结果已保存。
2. `450/60` 固定哈希链路也完整解析 200 个案例，说明 document/section 标签不依赖单一分片参数。
3. 后端全量测试和新增 v3 结构测试通过：213 passed，另有 15 个 subtests 通过。
4. Prompt 注入、无依据拒答、Top-K 召回和型号准确率已显著改善；引用支持率仍未达到 90% 生产门。
5. 失败样本审计发现部分固定标注只认可一个章节，而其他章节也包含直接支持事实。不得直接
   放宽标签抬高分数；应由独立人工复核后补充“同样有效的支持章节”，并另做最终答案语义忠实度评测。
6. 固定 v3 问题，不得通过删除失败样本改善分数。
