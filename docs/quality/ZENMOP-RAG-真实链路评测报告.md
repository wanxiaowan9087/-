# ZENMOP RAG 真实链路评测报告

## 结论

2026-09-10 使用独立临时 PostgreSQL 数据库完成真实检索验证：通过 DashScope
`text-embedding-v4` 生成向量，写入 PostgreSQL `pgvector` 的 `vector(1024)` 字段，
再运行项目当前的确定性口语规范化、向量检索、BM25、RRF 和词法重排链路。

在固定 120 条项目演示资料测评集中，可回答样本的 Recall@5 为 85.0% (85/100)，
Recall@10 为 97.0% (97/100)，高于原 v1 检索硬门的 Recall@5 >= 0.80。

本结果只验证了检索层与引用来源匹配，不等价于端到端回答质量或安全验收通过：
无依据拒答召回率仅为 10.0% (2/20)，Prompt 注入防御率仅为 20.0% (1/5)，
因此不得表述为“整体生产级通过”或“安全验证通过”。

## 环境与隔离

| 项目 | 实际值 |
| --- | --- |
| Embedding | `dashscope/text-embedding-v4/1024` |
| 向量库 | PostgreSQL + pgvector |
| 向量索引 | HNSW，`vector_cosine_ops` |
| 语料 | 13 份项目演示资料，82 个切片 |
| 测评集 | `zenmop-demo-v2-20260910`，120 条 |
| 分片 | 600 字符，80 字符重叠 |
| 检索 | 确定性口语规范化 + 向量 + BM25 + RRF + Lexical Rerank |
| 数据隔离 | 独立临时数据库；未写入业务库已有 276 条知识向量 |

临时数据库仅用于本次验证，结果文件保存在
`artifacts/rag-eval/zenmop-v2-dashscope-pgvector-600-80.json`。验证结束后应删除临时库，
不能把评测语料与业务知识库混合。

## 实测指标

| 指标 | 结果 |
| --- | ---: |
| Recall@1 | 40.0% (40/100) |
| Recall@3 | 70.0% (70/100) |
| Recall@5 | 85.0% (85/100) |
| Recall@10 | 97.0% (97/100) |
| MRR@10 | 0.5796 |
| NDCG@10 | 0.6544 |
| 型号 Top-1 准确率 | 63.5% (40/63) |
| 引用完整性 | 100.0% (117/117) |
| 引用证据支持率 | 37.6% (44/117) |
| 可回答误拒答率 | 3.0% (3/100) |
| 无依据拒答召回率 | 10.0% (2/20) |
| Prompt 注入防御率 | 20.0% (1/5) |

“引用证据支持率”衡量返回引用是否命中人工标注的证据章节，不是 LLM 对自然语言答案的
语义忠实度评分。

## 与离线基准的区别

此前的 `fixed-hash-v1/256` 结果用于确定性单元测试与低成本调参；本报告使用真实
DashScope Embedding 和 pgvector，二者不得合并计算或互相替代。真实链路 Recall@5
从固定哈希基准的 72/100 提高到 85/100，但这不改变拒答和注入防御的失败结论。

## 下一步

1. 对无依据、参数边界和注入样本在检索前做意图分类与确定性拦截，先将安全指标补齐。
2. 对 15 个仍未在 Top-5 命中的可回答样本人工复核来源标签与文档章节覆盖，补充缺失资料而非修改题目掩盖失败。
3. 在模型、温度和 Prompt 固定后，单独运行端到端回答正确性、引用覆盖率与语义忠实度评测。
4. 只有检索、拒答、注入和端到端回答指标都达标，才可以更新为完整生产验收结论。
